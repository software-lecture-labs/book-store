## Bağlam

Kullanım senaryoları HTTP üzerinden sunulacak *(API-1 – API-4)*. HTTP katmanı JSON dönüşümü, girdi doğrulama, yönlendirme ve hataların durum kodlarına çevrilmesi gibi tamamen teknik sorumluluklar taşır; bunların domain'e sızması iş kurallarını bir protokole bağlar. İstemcilerin hataları programatik olarak ayırt edebilmesi için de tutarlı bir hata gövdesi gerekir. Ders notları *(Bölüm 13)* bu katmanı önce JDK'nın HTTP sunucusuyla elle yazıp, sonra JAX-RS'e taşıyor *(Bölüm 14)*.

## Karar

1. Her iş modülünün `rest` paketi yalnızca kendi `api` paketini ve `shared-kernel`'i görür; kullanım senaryolarına `api` paketindeki façade arayüzleri *(`CatalogFacade`, `CartFacade`, `CheckoutFacade`, `AccountFacade`, `ReviewFacade`)* üzerinden erişir.
2. JSON, Bean Validation ve HTTP sunucusu tipleri yalnızca `rest` paketlerinde kullanılır. Hiçbir paket `rest`'e bağımlı değildir.
3. İstek gövdeleri `rest` paketindeki `record`'lara *(`AddToCartRequest`, `PlaceOrderRequest` …)* okunur ve Bean Validation ile **biçimsel olarak** doğrulanır; tüm hatalı alanlar tek yanıtta döner. İş kuralları domain'de kalır ve tekrar yazılmaz.
4. HTTP durum kodu, exception sınıfına göre değil `DomainException.Kind`'a göre belirlenir: `NOT_FOUND` → 404, `CONFLICT` → 409, `RULE_VIOLATION` → 422, `FORBIDDEN` → 403. Biçimsel doğrulama hataları 400'dür.
5. Tüm hata yanıtları RFC 9457 *(Problem Details)* biçiminde, `application/problem+json` medya tipiyle döner: `type`, `title`, `status`, `detail`, `code` ve gerekirse `errors` *(alan hataları)*. Beklenmeyen hatalar 500 döner; SQL, stack trace gibi iç ayrıntılar yanıta değil yalnızca kayda yazılır.
6. API sürümü URL'dedir: `/api/v1/...`.
7. Faz 5'te HTTP katmanı JDK HTTP sunucusu *(`com.sun.net.httpserver`)* ile elle yazılır *(ders Bölüm 13)*; Faz 6'da JAX-RS'e taşınır ve aynı HTTP testleri JerseyTest ile geçmeye devam eder.

## Değerlendirilen Alternatifler

| **Alternatif** | **Neden seçilmedi?** |
| --- | --- |
| Exception'ları somut sınıflarına göre eşlemek | `rest`'in domain'i görmesini gerektirir *(ADR-0003 ihlali)*; her yeni exception için tablo güncellenir. |
| Doğrulamayı yalnızca domain'e bırakmak | Domain ilk hatada durur; istemci beş hatalı alanı beş istekte öğrenir. |
| Özel hata gövdesi *(`{"error": "..."}`)* | RFC 9457 standarttır ve istemci kütüphanelerince tanınır. |
| Doğrudan JAX-RS ile başlamak | Runtime'ın bedavaya verdiği davranışlar *(405, 415, içerik pazarlığı)* elle görülmeden kullanılır. |

## Sonuçlar

- **Olumlu:** Yeni bir domain exception eklendiğinde HTTP katmanı değişmez; `Kind` durum kodunu, `code` istemcinin karar vereceği değeri belirler.
- **Olumsuz:** Bazı kurallar iki yerde ifade edilir *(adedin pozitif olması hem `@Positive` hem `CartItem` içinde)*. Kaynak gerçeklik domain'dir.
- **Risk:** `code` değerleri istemci sözleşmesidir; değişmemeleri testle sabitlenir.
